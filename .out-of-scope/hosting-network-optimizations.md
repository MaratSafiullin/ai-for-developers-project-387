# Оптимизация раздачи и сетевого пути страницы

Мы не оптимизируем то, как сервер отдаёт ресурсы, и порядок, в котором страница их загружает. Сюда относятся долгий `Cache-Control` для статики, вынос критического CSS и сокращение цепочек критичных запросов. Lighthouse отмечает это аудитами `cache-insight`, `render-blocking-insight` и `network-dependency-tree-insight`.

Сокращение неиспользуемого JS в эту запись не входит: это правка кода приложения, а не раздачи. См. `vendor-runtime-javascript.md`.

## Почему не делаем

### Статику отдаёт встроенный сервер PHP

В проде приложение работает на встроенном сервере PHP: `docker-entrypoint.sh` запускает `php artisan serve`. Если запрошенный файл есть в `public/`, роутер Laravel (`vendor/laravel/framework/src/Illuminate/Foundation/resources/server.php`) возвращает `false`, и файл отдаёт сам встроенный сервер, без заголовков кеширования. Laravel до таких запросов не доходит, поэтому middleware не поможет, а `public/.htaccess` не действует: Apache в образе нет.

К тому же встроенный сервер обрабатывает запросы по одному. Браузер запрашивает чанки и шрифты параллельно, через `modulepreload` и `preload`, но на деле они приходят друг за другом. Отсюда и длинные цепочки в отчёте.

Чтобы это исправить, нужен свой роутер для `php -S`, который сам отдаёт файлы с нужными заголовками, или настоящий веб-сервер в образе: FrankenPHP/Caddy или nginx + php-fpm. Первое добавляет самописную раздачу статики, второе меняет образ и деплой.

### Данные страницы приходят после JS

Цепочка «HTML → JS → запрос данных через SDK» заложена в [ADR 0001](../docs/adr/0001-inertia-pages-sdk-data.md): данные страница получает через сгенерированный SDK, а не через props Inertia. Сократить её можно только отказом от этого решения.

### Блокирует отрисовку только CSS

Модульные скрипты отрисовку не блокируют, поэтому из блокирующего на странице остаётся только `app.css`. Это SPA: контент рисует JS, и LCP ждёт JS, а не стили. Вынос критического CSS усложнит сборку почти без выигрыша.

### Итог

Для учебного проекта на бесплатном тарифе Render это не окупается: демо посещают редко, а заметная часть задержки — холодный старт и удалённость хостинга.

Аудит производительности (`perf-audit.yml`) эти находки не перезаводит: последний закрытый issue с их маркером помечен `wontfix`.
