# Неиспользуемый JS в общем рантайме

Мы не добиваемся того, чтобы Lighthouse перестал отмечать аудит `unused-javascript` на гостевых страницах `/` и `/book`. Его остаток приходится на общий вендорный чанк, без которого не работает ни одна страница.

## Что уже сделано

В #66 (PR #74) из корня приложения убраны `TooltipProvider` и глобальный `Toaster`. Entry-чанк уменьшился с 40.83 до 38.43 kB, а гостевые страницы больше не загружают sonner и Radix Popper. Оценка Lighthouse от этого почти не изменилась: до правки экономия была 72 KiB на `/` и 68 KiB на `/book`. Прогон после деплоя показал 72 и 67 KiB (#75).

## Почему не делаем дальше

Каждой странице нужен чанк `compiler-runtime-*.js`: около 348 kB, 108 kB в gzip. В нём React DOM, Inertia и общие зависимости. При первой отрисовке выполняется только часть этого кода, а Lighthouse считает остаток неиспользуемым. Разбивку экономии по файлам мы не смотрели. Остальные чанки `/book` вместе с entry весят около 36 kB в gzip, у `/` ещё меньше, так что основная часть остатка, скорее всего, приходится на этот чанк.

Чтобы сократить остаток, пришлось бы вручную настроить чанки (`manualChunks`) и вынести `QueryClientProvider` из корня. Тогда React Query грузился бы только на страницах, которые получают данные через SDK. Это усложнит сборку, а выигрыш непредсказуем: React DOM и Inertia всё равно нужны целиком. Для учебного демо, которое посещают редко, это не окупается.

Аудит производительности (`perf-audit.yml`) эту находку не перезаводит: последний закрытый issue с её маркером помечен `wontfix`.
