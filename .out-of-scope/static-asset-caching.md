# Долгое кеширование статики

Приложение не отдаёт файлы сборки Vite (`public/build/assets/*`) с долгим `Cache-Control` вроде `public, max-age=31536000, immutable`. Lighthouse отмечает это аудитом `cache-insight`. На страницах `/` и `/book` повторный визит мог бы сэкономить около 280–290 KiB.

## Почему не делаем

В проде приложение работает на встроенном сервере PHP: `docker-entrypoint.sh` запускает `php artisan serve`. Если запрошенный файл есть в `public/`, роутер Laravel (`vendor/laravel/framework/src/Illuminate/Foundation/resources/server.php`) возвращает `false`, и файл отдаёт сам встроенный сервер, без заголовков кеширования. Laravel до таких запросов не доходит, поэтому middleware не поможет, а `public/.htaccess` не действует: Apache в образе нет.

Чтобы поставить заголовки, нужен один из двух путей:

- свой роутер для `php -S`, который сам отдаёт файлы из `/build/assets/` с нужным заголовком и Content-Type;
- настоящий веб-сервер в образе: FrankenPHP/Caddy или nginx + php-fpm.

Для учебного проекта на бесплатном тарифе Render оба пути не окупаются. Первый добавляет самописную раздачу статики, второй меняет образ и деплой. Выигрыш есть только у повторных визитов, а демо посещают редко.

Аудит производительности (`perf-audit.yml`) находку не перезаводит: последний закрытый issue с её маркером помечен `wontfix`.
